# 0ne//hub — установка Hysteria 2

Интерактивный Bash-установщик Remnanode для Debian 11+ и Ubuntu 20.04+ с systemd. Нужны root, Bash 4+, Python 3.8+, curl и домен, указывающий на сервер. Предназначен для новой ноды; существующие `/opt/remnanode`, `/opt/hysteria` и конфигурацию этого установщика не перезаписывает.

## Запуск

Скопируйте `install.sh` на Linux-сервер и выполните:

```bash
sudo bash install.sh
```

Если Python/curl ещё не установлены:

```bash
sudo apt-get update
sudo apt-get install -y python3 curl ca-certificates
sudo bash install.sh
```

Меню: установка, очистка изменений установщика, диагностика, выход. Разделители и `/` в заголовках красные при запуске в терминале; после заголовка нет пустой строки. Подсказка в скобках у SECRET_KEY серая. Подтверждения используют `[y/N]`: `y`/`yes` подтверждает, Enter отменяет. `NO_COLOR=1` отключает цвет.

Установка спрашивает домен, TCP-порт API ноды (по умолчанию 2222), IP/домен панели и SECRET_KEY. Для панели вводится адрес без `https://`, пути или порта; для IPv6 — адрес без квадратных скобок. Секрет и лицензия вводятся скрыто. Домен ноды должен иметь корректные A/AAAA без CDN-проксирования. Проверяются все найденные адреса.

## HTML и лицензия

В меню ровно десять указанных макетов: 503, Первое облако, Формат, Downloadlify, לוי אורבך, Лекторий Плюс, Omnify, Эфир, Братский союз, Поток.

Лицензия берётся из `ONEHUB_LICENSE_KEY`, которую передаёт bootstrap 0ne//hub (см. `onehub/lib/script-delivery.js`). При обычном запуске ключ запрашивается. Тестового ключа в проекте нет. URL формируется во время запуска: `https://api.0nehub.xyz/files/k/{license_key}/{file_id}`. Он передаётся curl через stdin и не выводится в диагностике. Скачивание происходит до итогового подтверждения; ошибочный ответ API останавливает установку до изменений сервисов.

При согласии на рандомизацию меняется только цветовая палитра: один из 10 000 поворотов цветового круга. Название сайта, логотип, текст и JavaScript остаются исходными. Изменяются цвета в CSS и SVG-атрибутах с сохранением яркости, нейтральных оттенков и прозрачности. Учтены CSS-переменные девяти макетов и статические цвета «Братского союза». Без согласия файл остаётся исходным. Рандомизация не запускается повторно при продлении сертификата.

## Развёртывание

После сводки и подтверждения скрипт:

- Устанавливает зависимости, Docker через официальный `get.docker.com`, проверяет Compose plugin.
- Создаёт контейнер `remnanode` из `remnawave/node:latest`, с `network_mode: host`, `NET_ADMIN`, лимитом файлов 1048576 и вашим SECRET_KEY. Compose хранится в `/opt/remnanode/docker-compose.yml` с правами 600. Файл имеет формат JSON, допустимый в YAML/Compose; `$` в секрете экранируется для Compose.
- Устанавливает отдельный acme.sh в `/opt/onehub-hy2/acme`, выпускает ECC-сертификат Let’s Encrypt через standalone HTTP-01. nginx временно останавливается и восстанавливается при завершении/ошибке. Занятые другим веб-сервером порты проверяются до установки.
- Устанавливает сертификаты через `--install-cert` в `/opt/hysteria/certs/privkey.pem` и `fullchain.pem`, монтирует каталог в контейнер только для чтения.
- Размещает HTML в `/opt/onehub-hy2/www/index.html`; nginx обслуживает домен на 80/TCP и 443/TCP. Каталог HTML также доступен контейнеру как `/var/www/html` для HTTP/3 masquerade.
- Настраивает UFW: 80/TCP и 443/TCP для сайта, **443/UDP для Hysteria 2**, выбранный TCP-порт ноды — только с IP панели. Запрет остальных источников для порта ноды расположен перед прежними общими разрешениями. Определённые SSH-порты разрешаются перед включением UFW. Существующие правила с портом ноды требуют ручного разбора или выбора другого порта до установки. Для IPv6 требуется штатное `IPV6=yes` в UFW.
- Добавляет `/etc/cron.d/onehub-hy2`: ежедневная проверка продления в 03:17 и дополнительный перезапуск ноды `0 4 1 */2 *`. Время берётся с сервера.

При реальном обновлении acme.sh копирует сертификат в рабочий каталог и вызывает `reload.sh`, который перезапускает Remnanode. `renew.sh` восстанавливает nginx даже при ошибке ACME. Параллельные запуск установщика и продление защищены `flock`. Перезапуск раз в два месяца — дополнительная задача, продлением занимается ежедневная проверка.

IP домена панели фиксируются в правилах UFW в момент установки. Если адрес панели изменится, обновите разрешения. Ограничения cloud firewall провайдера настраиваются отдельно: скрипт управляет локальным UFW.

## Завершение в Remnawave

Установщик поднимает Remnanode и инфраструктуру. Профиль Hysteria 2 и пользователей применяет панель: у скрипта нет её административного API-токена.

1. В панели добавьте/завершите создание ноды с введённым адресом, портом и SECRET_KEY.
2. В профиле добавьте inbound Hysteria 2 на 443/UDP с сертификатами по путям выше. Пример профиля скрипт сохраняет в `/opt/onehub-hy2/panel-profile.json`; при существующем профиле перенесите нужный inbound, сохранив свои routing/outbounds. В примере пользователи пустые — ими управляет панель.
3. Назначьте профиль ноде, настройте Host и доступ пользователей в панели. Убедитесь, что версия панели/ядра поддерживает Hysteria 2. До применения профиля запущенный контейнер сам по себе ещё не означает работающий Hysteria inbound.

Пример включает `hysteriaSettings.masquerade` типа `file` из `/var/www/html`, TLS с ALPN `h3` и пути к сертификатам. nginx на 443/TCP и Hysteria на 443/UDP могут работать одновременно.

Официальные описания: [установка Remnanode](https://docs.rw/install/remnawave-node/), [Hysteria inbound](https://xtls.github.io/config/inbounds/hysteria.html), [Hysteria transport и masquerade](https://xtls.github.io/ru/config/transports/hysteria.html), [acme.sh и install-cert](https://github.com/acmesh-official/acme.sh), [установка Docker](https://docs.docker.com/engine/install/ubuntu/).

## Очистка и диагностика

Пункт 2 удаляет контейнер/Compose, сертификаты, сайт, изолированный acme.sh и cron этого установщика. Из UFW удаляются только собственные правила; если UFW изменил комментарий существовавшего правила, он восстанавливается по снимку `ufw-before.txt`. Если до установки UFW был выключен, он выключается обратно. nginx останавливается, если до установки он не работал. Очистка доступна и после частичной установки.

Docker, скачанный Docker-образ и системные пакеты остаются установленными. Другие контейнеры и конфигурации сайтов не удаляются. После очистки пакеты и зависимости можно обслуживать отдельно.

Пункт 3 показывает службы, контейнер, порты, UFW, DNS, сроки сертификата, наличие cron и результат запроса HTTPS. Содержимое Compose, окружение контейнера и логи приложения не выводятся, чтобы не раскрыть секреты. Журнал продления: `/opt/onehub-hy2/renew.log`.

## Ошибка Invalid position при установке UFW

В исправленной версии используется `ufw prepend` вместо `ufw insert 1`: добавление в начало работает и при пустом списке, отдельно для IPv4/IPv6. Если предыдущая версия остановилась на `ERROR: Invalid position '1'`, замените скрипт исправленным, запустите его, выберите пункт 2 для очистки частичной установки, затем пункт 1. Общий сброс UFW не требуется.

## Ошибка acme.sh Unknown parameter: ----install

Исправлено обращение к установщику: скрипт скачивает официальный `acme.sh` из репозитория и вызывает `--install-online --home ... --config-home ... --nocron --noprofile`. Wrapper `get.acme.sh` интерпретировал первый `--install` как параметр email, добавляя к нему ещё два дефиса, и не передавал ошибку установки вызывающему процессу. Теперь проверяются код завершения, наличие рабочего файла и запуск `--version`.

Исправленный путь проверен реальной установкой acme.sh 3.1.7 в изолированном временном каталоге macOS, без cron, изменений shell-профиля и выпуска сертификата. Дополнительные тесты проверяют аргументы, неуспешную установку и отсутствие выходного файла. Проверка Linux VPS целиком по-прежнему не выполнена.

Если запуск идёт из библиотеки 0ne//hub, обновите в ней `install.sh`; временная копия `/tmp/onehub-script.*/install.sh` пересоздаётся при следующем запуске. Для повторной установки запустите обновлённый скрипт, очистите частичную установку пунктом 2, затем выберите пункт 1. Docker останется установленным.
